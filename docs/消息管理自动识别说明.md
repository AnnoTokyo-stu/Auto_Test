# 消息管理自动识别说明

## 选择策略

页面上存在多个同名“详情”按钮，项目不使用 `nth-child` 或固定行号，而是按以下优先级选择消息：

1. `message_id` 非空时，精确匹配消息 ID。
2. 匹配指定状态：`已读` 或 `未读`。
3. `title_contains` 非空时，再匹配标题关键字。
4. 条件全部满足后，选择当前排序下的第一条记录。
5. 当前页没有目标时，自动翻页，最多检查 20 页。

配置文件位于：

```text
data/message_data.json
```

保持 `message_id` 和 `title_contains` 为空即为纯自动选择；需要精确复测时再填写指定 ID 或标题关键字。

数据提供方账号凭据保存在本机 `.env.local`：

```dotenv
TEST_DATA_PROVIDER_NAME=""
TEST_DATA_PROVIDER_PASSWORD=""
```

如果当前 `TEST_USER_NAME` 本身就是数据提供方账号，可以不配置上述两个专用变量，消息用例会自动复用：

```dotenv
TEST_USER_NAME="test2"
TEST_USER_PASSWORD="对应密码"
TEST_USER_DISPLAY_NAME="test2"
```

当专用变量和通用变量同时存在时，优先使用 `TEST_DATA_PROVIDER_*`。不要把真实凭据写入 `message_data.json`。

## 定位技术

- 先读取 `#pane-message` 下表格的所有 `tbody > tr`。
- 根据六个 `td` 顺序解析消息 ID、标题、内容、发送时间、状态和操作列。
- 选中目标记录后，在该行内部使用相对 XPath 查找文字为“详情”的按钮。
- 因此新增消息、列表重排和分页不会造成点击错行。

## 状态校验

- 已读消息：打开详情后仍应为已读。
- 未读消息：打开详情后应转为已读。
- “全部已读”只检查可见且启用，不点击，避免批量破坏后续测试数据。
- “点击查看”只检查可用性，不点击，不跳转到其他业务页面。

## 执行命令

```powershell
python -m pytest script/test_03_message_management.py::test_web_074_auto_select_read_and_unread_message_details --run-ui --run-destructive -s
```

该用例会把一条未读消息变成已读，因此需要 `--run-destructive`。
