## 补全原则

1. 每次新增仍使用稳定且唯一的 `WEB-xxx` 编号，不自创业务预期。
2. 优先补充稳定、可重复、数据可恢复的 P0 场景。
3. 审核、对账、传输中断等场景先解决测试环境控制能力，再写 UI 自动化。
4. 每批完成后更新本文件；原 73 条应保持“已构建 19 + 待补全 54 = 73”，实际测试扩展另行累计。
