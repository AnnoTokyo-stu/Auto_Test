# 数据提供方认证资料填写运行指南

## 1. 当前自动化范围

当前实现对应原测试用例 `WEB-011` 的“数据提供方认证资料填写”阶段：

1. 使用 `.env.local` 中的测试用户登录。
2. 进入“运营管理后台”。
3. 打开“数据提供方认证”。
4. 填写主体、法定代表人、经办人和 CNY 收款账户。
5. 校验关键字段与附件填写结果。
6. 停留在“提交”前供人工审查。

当前不会点击生产环境的“提交”，因此尚未覆盖人工审核通过、游客角色替换、权限即时生效等后续预期。

## 2. 模拟数据位置

业务模拟数据统一保存在：

```text
data/data_provider_certification.json
```

账号密码继续读取本机 `.env.local`，不会复制到 JSON 中。若页面下拉框的真实选项文字不同，只修改 JSON 中对应值，不修改页面对象或测试脚本。

## 3. 附件准备

将模拟图片放入：

```text
test_materials/
```

文件名必须为：

```text
business_license.png
legal_representative_id.png
operator_id.png
```

每个文件仅允许 PNG、JPG、JPEG、PDF，且不能超过 2 MB。不要使用真实证件或生产资料。

## 4. 运行命令

```powershell
python -m pytest script/test_02_data_provider_certification.py::test_web_011_fill_data_provider_certification_for_review --run-ui --run-destructive -s
```

`--run-destructive` 用于明确允许向生产服务上传模拟附件。用例仍不会提交认证申请。

## 5. 首次执行注意事项

- 登录图形验证码仍由人工输入。
- 如果提示“下拉选项未出现”，记录页面实际选项文字并修改 JSON。
- 如果定位失败，保留失败截图并复制相应字段所在 `el-form-item` 的 `outerHTML`。
- 首次完整填写成功后先人工核对所有页面数据，不手动点击提交。

## 6. 长页面滚动与填写速度

- 公共页面操作会在点击、输入前自动把元素滚动到视口中部，也会处理可滚动的祖先容器。
- 默认 `WEB_FAST_INPUT=true`，文本框使用原生 value setter 并触发 `input`、`change` 事件，减少长表单填写时间。
- 如果实际页面的个别控件无法接收快速输入，可在 `.env.local` 中设置 `WEB_FAST_INPUT=false`，统一回退到 Selenium `send_keys`。
- 密码规则、字符长度、键盘输入联动等输入控件专项用例必须设置 `WEB_FAST_INPUT=false`，避免快速赋值绕过逐键行为；主流程资料填写可保持 `true`。
